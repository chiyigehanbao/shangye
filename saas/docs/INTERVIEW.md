# 面试讲解提纲

> 时间紧张时先读 [`QUICK-INTERVIEW.md`](QUICK-INTERVIEW.md)（30 分钟速览）；本文用于展开细节。

> 目标：用 3 分钟讲清“为什么这是一个产品，而不是四个页面”。

## 1. 一句话介绍

FlowDesk 是一个面向小团队的 AI 办公自动化工作台：把 Excel 清洗、合同字段抽取、报价单和销售看板收进同一个多租户 SaaS，带账号、套餐、配额、计费、审计和可降级的 AI。

## 2. 30 秒架构

- 一个 FastAPI 单体 + 一个 SQLite（WAL）+ 一个 Nginx；
- 前端原生 HTML/CSS/JS，本地 Chart.js，无构建步骤；
- 文档批量任务用 SQLite 队列 + 单 worker 线程；
- AI 走“云 API → Ollama → 规则引擎”，任何一层失败都不阻塞业务；
- 整个系统只跑一个 uvicorn worker，目标就是 2 核 2G。

## 3. 高频问题与回答

### Q1：为什么不做微服务？

2C2G 上启动 7–15 个服务，内存先不够，然后还要重复做鉴权、网关、数据库、日志。现在把模块边界放在代码层，路由和服务已经隔离；将来按模块拆出去即可。先保证“能部署、能演示、能维护”。

### Q2：为什么用 SQLite，不用 PostgreSQL？

小团队、低并发、单机部署，SQLite 的运维成本最低，WAL 足够支撑读写。数据层集中在 `database.py`，迁移 PostgreSQL 时业务代码基本不动。真正的瓶颈是长任务和并发写，不是查询复杂度。

### Q3：多租户怎么隔离？

所有业务表都有 `workspace_id`；登录后会话绑定当前工作区；每个查询都带租户条件；角色来自 `memberships`。平台管理员和租户管理员是两套权限。测试里专门验证了“新注册用户看不到演示工作区的报价/文档/分析”。

### Q4：配额怎么保证不超卖？

`quota.check` 在任务执行前检查任务数、存储、成员数；`quota.consume` 在成功后写 `usage_events`。套餐定义只有一份，前后端共用。演示环境是沙箱计费，但订阅、发票、套餐切换、取消的闭环是真实可验证的。

### Q5：AI 不可用怎么办？

三层降级：云 API → 本地 Ollama → 规则引擎。业务只调用 `ai.py` 的业务函数，返回值带 `provider`，前端显示来源，`ai_logs` 记录耗时。最差也能用规则给出可解释结果，不会因为网络问题让演示冷场。

### Q6：文档批量任务怎么保证可靠？

任务落 SQLite，状态机 `pending → processing → done/failed/canceled`；`claim_next` 用 `BEGIN IMMEDIATE` 原子领取；失败按 `max_attempts` 重试；取消是协作式的；服务重启时回收遗留的 `processing` 任务。代价是单进程，这是 2C2G 的主动取舍。

### Q7：为什么不用 JWT？

JWT 无法立即撤销，服务端还要维护黑名单；opaque token 存数据库，登出、禁用用户、切换工作区都能立即生效，服务重启也不掉登录。代价是每次请求多一次索引查询，这个量级完全可以接受。

### Q8：2C2G 怎么跑得动 pandas？

- 单 worker，避免多进程复制 pandas 内存；
- 上传限制 15MB、分析限制 2 万行；
- 文档 worker 单线程；
- Nginx 直接返回静态资源；
- 不跑本地大模型，AI 走云 API 或规则；
- 导出分批/流式，避免一次性构造巨大对象。

### Q9：这个项目的商业闭环是什么？

Free 试用 → Pro/Team 订阅（沙箱）→ 任务/存储/成员配额 → 发票与用量 → 平台后台看 MRR、任务量、AI 调用。不是“画了一个定价页”，而是套餐真的会改变配额。

### Q10：如果用户量涨 100 倍，你先改什么？

先拆三件事：PostgreSQL、独立 worker、对象存储。然后 Excel 会话外置到 Redis，Nginx 多实例，最后才考虑按模块拆服务。不会为了“架构先进”提前引入这些复杂度。

## 4. 现场演示顺序

1. 落地页：定位与设计系统；
2. 演示账号登录：多租户、会话、套餐；
3. Dashboard：用量、最近活动、AI 状态；
4. Excel：上传 → 清洗 → 自然语言汇总 → 导出；
5. 文档：抽取 → 批量队列 → 重试/取消；
6. 报价：编辑 → 打印 → AI 生成条目；
7. 销售看板：上传 → KPI/图表 → AI 洞察；
8. 计费：套餐/发票/配额闭环；
9. 设置：成员、审计；
10. 平台后台：全局视角。

完整脚本见 [`DEMO.md`](DEMO.md)。

## 5. 可以主动指出的不足

- 计费是沙箱，不接真实支付；
- 邀请链接需手动复制，没有邮件服务；
- Excel 上传会话在进程内，不能多实例；
- SQLite 不适合高并发写；
- 前端没有构建链，工程化程度不如 React/Vue 项目；
- 多语言、无障碍和移动端还可以继续打磨。

主动说不足，比被问出来更加分；同时给出每条不足的迁移路径。
